# 차비스 — 기획서

현대자동차그룹 차량용 앱 개발 공모전 (Pleos App Market) · 일반 부문 · 개인 참가

> 내비는 길을, 차비스는 가족의 다음 장소를 이어 줍니다.
> 코스는 한 번 계획하고, 드라이브는 차가 이어서 안내하고, 만족도는 다음 추천으로.

## 1. 한 줄 소개

주말에 아이와 여러 곳을 들르는 가족 드라이브에서, 앱으로 코스를 한 번 계획하면 **다시 출발할 때마다 다음 장소를 차가 알아서 안내**하고, 집에 돌아오면 **만족도 리뷰**를 받아 다음 코스 추천을 더 잘 맞추는 Pleos Connect 앱입니다.

## 2. 문제

| 순간 | 실제 불편 |
|---|---|
| 계획 | 박물관 → 점심 → 공원처럼 여러 곳을 들르는 코스를 따로 메모하고 순서를 기억해야 한다 |
| 출발할 때마다 | 장소를 옮길 때마다 내비에 다음 목적지를 다시 검색한다. 아이를 태우고 서두르다 보면 주행 중 조작으로 이어진다 |
| 다녀온 뒤 | 어디가 좋았는지 기록이 남지 않아 다음 주말 코스도 처음부터 다시 고민한다 |

일반 내비는 "한 번에 한 목적지"까지만 안내합니다. 하루 코스 전체, 다시 탈 때의 다음 장소, 다녀온 뒤의 만족도는 아무도 이어 주지 않습니다.

## 3. 사용 흐름

1. **평일에 휴대폰으로 계획**: 테마 코스(아이와 함께·힐링·체험·맛집·문화) 선택 → 이번 주 토요일 오전으로 일정 저장 ("그날 차에 시동을 걸면 바로 안내해 드려요")
2. **주말에 시동 → 드라이브 팝업**: 차에서 앱이 켜지면(시동 ON) 예정 코스를 찾아 "계획한 드라이브가 있어요" → **출발하기**를 누르면 계획한 순서대로 첫 목적지를 차량 내비에 넘겨 안내 (차에서 바로 코스를 잡으면 "드라이브를 시작할까요?")
3. **도착**: 내비 도착 신호(또는 주차 P)로 자동 도착 처리. 도착지의 혼잡·주차 정보와 우회 제안을 보여 줌
4. **다시 시동 → 다음 장소**: 기어 P→D(또는 앱 재실행 시 진행 상태 복원)로 다시 출발을 감지해, 화면 터치 없이 "다음 목적지, ○○로 안내를 시작합니다"를 음성으로 알리고 다음 경로를 요청
5. **귀가 후 리뷰**: 마지막 장소에서 출발하면 루트 완료. 집에 도착해 차를 세우면 장소별 별점 + 한 줄 소감을 남김(주행 중에는 잠금)
6. **다음 추천**: 긍정 리뷰가 많은 코스에 가중치를 두어 테마 추천에 반영

## 4. 왜 차에서인가 (차량특화성)

| 차량 신호 (Pleos SDK) | 차비스가 하는 일 |
|---|---|
| NaviHelper `requestRoute` | 장소별 경로를 시스템 내비에 바로 요청 — 목적지 재검색 없음 |
| NaviHelper 도착 이벤트 | 목적지·경유지 도착을 자동으로 처리 (중간 정차의 P는 도착으로 보지 않음) |
| Vehicle 기어 P→D | 재출발(시동) 신호 — 다음 장소를 터치 없이 음성 안내 |
| Vehicle 기어 D/R | 주행 중에는 계획·추천·리뷰 편집을 잠가 운전 집중 |

시동 ON/OFF API가 없어 **기어 P→D**와 **앱 재실행 시 진행 상태 복원**을 함께 써서 "다시 시동하면 다음 장소"를 구현했습니다.

## 5. 기술 구조

- Android(Kotlin, Jetpack Compose) 단일 앱. 가로(차량)·세로(폰) 화면을 함께 지원
- `TripViewModel` 주행 상태 머신: 대기 → 안내 중 → 도착 → 다음 확인 → 완료 → 리뷰
- `TripProgressStore`: 진행 상태를 저장해 앱이 다시 켜져도 이어서 안내
- `ResilientNaviGateway`: Pleos NaviHelper가 연결되지 않으면 Mock으로 전환(폰 시연용)
- `CourseRecommender`: 리뷰 만족도 가중 코스 추천

## 6. 시연 영상

`demo/chavis-usage.mp4` (1분 58초). 수요일 밤 휴대폰으로 토요일 코스를 계획하고, 토요일 아침 시동을 걸면 차에 그 계획이 떠서 드라이브를 시작하는 흐름입니다. 조개섬 캐릭터 가족이 등장하는 상황 연출 사이에, **실제 APK를 휴대폰 에뮬레이터와 Pleos Connect Emulator 2.1.0에서 녹화한 화면**을 넣었습니다. 시동은 앱 실행으로, 기어는 Virtual Console로 바꿨고, 내비 화면은 에뮬레이터의 실제 시스템 내비입니다.

## 7. 사업성과 확장

- 대상: 주말·휴가철에 자녀와 여러 곳을 들르는 30~40대 가족 운전자. Pleos 탑재 차종 핵심 구매층과 겹칩니다.
- 수익 모델: 제휴 장소(체험관·식당·키즈카페) 노출 → 코스 내 예약·결제 수수료(Pleos Payment SDK 공개 후) → 지자체·관광공사 코스 큐레이션(B2G)
- 확장: 서울·수도권 코스에서 시작해 제주·대전·경주 등 전국 테마 코스로. 리뷰가 쌓일수록 지역별 가족 코스 추천이 정확해집니다.

## 8. 현재 한계

- 장소·혼잡·주차 정보 일부는 시연용 추정값입니다. 실서비스는 관광 API와 제휴 데이터로 바꿉니다.
- 음성 명령(STT)은 로드맵입니다. 현재는 음성 안내(TTS)와 화면 칩으로 시뮬레이션합니다.
- 계정과 계획은 기기 안에 저장합니다. 실서비스는 Pleos 계정 연동으로 폰에서 세운 계획을 차가 그대로 받습니다. 시연에서는 차량 에뮬레이터에도 같은 코스를 미리 저장해 두었습니다.
